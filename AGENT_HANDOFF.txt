PART 2: THE PROJECT
-------------------
An agent on a laptop. The user types a web task. It captures the screen,
finds elements, picks one, uses mouse/keyboard, checks whether the action
worked, then continues, recovers or stops.

  planner -> capture before -> screen parser + OCR -> grounding
  -> executor -> wait -> capture after -> verifier
  -> continue / retry / replan / stop

Three ML models: (1) screen parser, (2) grounding model, (3) verifier,
which is the MAIN CONTRIBUTION. The planner is not one of the three;
rule-based is suggested at first.

Research focus: does a small local verifier improve task success, and what
does it cost in time and memory? Compare: no verifier, pixel-difference
rule, trained verifier, larger vision-language model. Without a verifier
there are no retries, so this measures verification plus recovery.

Key rules: while running, the agent uses screenshots, not the DOM (DOM is
only for labels and scoring). Split data by site/template. Tune only on
validation data. Practice sites and fake accounts only, with a step limit
and stop key. Never invent results or references.

Unclear in the proposal: title says "Web-Based Application" but the text
describes a desktop app; the abstract mentions a "team".

Voice commands: optional, not in the approved proposal, needs supervisor
approval, only after M9 (guide section 24).

The proposal PDF was attached in an earlier chat. It was not seen in the
project folder. If you need it, ask me. Do not commit it.
